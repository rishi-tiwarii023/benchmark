# Statistics Endpoint Implementation

## Overview
Added a new GET `/tasks/stats` endpoint that returns task statistics calculated from the database, with clear separation of concerns across layers.

## Changes Made

### 1. **New Schema: `app/schemas/stats.py`**
Created response schema for statistics:

```python
class TaskStats(BaseModel):
    total: int
    pending: int
    completed: int
    high_priority: int
```

**Benefits:**
- Type-safe response validation
- Clear definition of what stats are returned
- Can be extended easily for new metrics

### 2. **Repository Layer: `app/repository/task.py`**
Added `get_stats()` method to TaskRepository:

```python
def get_stats(self) -> dict:
    """Get task statistics."""
    total = self.db.query(func.count(Task.id)).scalar() or 0
    pending = self.db.query(func.count(Task.id)).filter(Task.status == "pending").scalar() or 0
    completed = self.db.query(func.count(Task.id)).filter(Task.status == "done").scalar() or 0
    high_priority = self.db.query(func.count(Task.id)).filter(Task.priority == "high").scalar() or 0
    
    return {
        "total": total,
        "pending": pending,
        "completed": completed,
        "high_priority": high_priority,
    }
```

**Benefits:**
- Encapsulates database queries
- Uses SQLAlchemy's `func.count()` for efficient counting
- Handles null results (converts None to 0)
- Easy to add more statistics without changing services or routes

### 3. **Service Layer: `app/services/task.py`**
Added `get_stats()` service function:

```python
def get_stats(db: Session) -> dict:
    """Get task statistics."""
    repo = get_repository(db)
    return repo.get_stats()
```

**Benefits:**
- Thin coordination layer
- Delegates to repository
- Could add business logic if needed in future
- Maintains consistent pattern with other services

### 4. **API Route: `app/routes/tasks.py`**
Added statistics endpoint:

```python
@router.get("/stats", response_model=TaskStats)
def get_task_stats(db: Session = Depends(get_db)):
    """Get task statistics."""
    stats = task_service.get_stats(db)
    return stats
```

**Key Points:**
- Route placed BEFORE `/{task_id}` to prevent path collision
- Uses automatic response validation with `response_model=TaskStats`
- Clear, simple handler

## API Endpoint

### Request
```
GET /tasks/stats
```

### Response (200 OK)
```json
{
  "total": 10,
  "pending": 4,
  "completed": 6,
  "high_priority": 3
}
```

### Metrics

| Metric | Description |
|--------|---|
| `total` | Total number of tasks in database |
| `pending` | Tasks with status = "pending" |
| `completed` | Tasks with status = "done" |
| `high_priority` | Tasks with priority = "high" |

## Separation of Concerns

### Architecture Flow
```
HTTP Request
    ↓
routes.get_task_stats() [HTTP handler]
    ↓
services.get_stats() [Coordination]
    ↓
repository.get_stats() [Database access]
    ↓
SQLAlchemy queries [ORM]
    ↓
Database
    ↓
Response (TaskStats schema)
```

**Each layer has a single responsibility:**
1. **Routes** - Handle HTTP, validate schema, error handling
2. **Services** - Coordinate and orchestrate
3. **Repository** - Database queries and operations
4. **Schemas** - Request/response validation

## Database Efficiency

The statistics endpoint uses SQLAlchemy's `func.count()` for efficient database queries:

```sql
-- Efficient queries sent to database
SELECT COUNT(*) FROM tasks;
SELECT COUNT(*) FROM tasks WHERE status = 'pending';
SELECT COUNT(*) FROM tasks WHERE status = 'done';
SELECT COUNT(*) FROM tasks WHERE priority = 'high';
```

**Benefits:**
- Count operations are very fast
- Minimal data transfer from database
- Works efficiently even with millions of tasks
- No need to load all task objects
