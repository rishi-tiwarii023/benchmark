# Changes Summary

## Added Filtering Support to GET /tasks Endpoint

### Files Modified

#### 1. app/routes/tasks.py
Updated the `list_tasks` route handler to accept optional query parameters for status and priority filtering.

```python
@router.get("", response_model=list[TaskRead])
def list_tasks(status: str | None = None, priority: str | None = None, db: Session = Depends(get_db)):
    return task_service.list_tasks(db, status=status, priority=priority)
```

**Query Parameters:**
- `status` (optional): Filter tasks by status value (e.g., "pending", "done")
- `priority` (optional): Filter tasks by priority value (e.g., "low", "medium", "high")

#### 2. app/services/task.py
Updated the `list_tasks()` function to support optional filtering based on status and priority.

```python
def list_tasks(db: Session, status: str | None = None, priority: str | None = None) -> list[Task]:
    query = db.query(Task)
    if status:
        query = query.filter(Task.status == status)
    if priority:
        query = query.filter(Task.priority == priority)
    return query.order_by(Task.id).all()
```

**Behavior:**
- When no filters are provided: Returns all tasks (original behavior)
- When status filter is provided: Returns only tasks with matching status
- When priority filter is provided: Returns only tasks with matching priority
- When both filters are provided: Returns only tasks matching both conditions

#### 3. tests/test_tasks_api.py
Added 4 new tests for filtering functionality:

**test_filter_by_status()**
- Creates tasks with different statuses (pending, done)
- Verifies filtering by status parameter returns correct tasks

**test_filter_by_priority()**
- Creates tasks with different priorities (high, low)
- Verifies filtering by priority parameter returns correct tasks

**test_filter_by_status_and_priority()**
- Creates tasks with various combinations of status and priority
- Verifies both filters work together to narrow results

**test_filter_no_results()**
- Verifies endpoint returns empty array when no tasks match filter criteria

### Example Usage

```
GET /tasks                          → Returns all tasks
GET /tasks?status=pending           → Returns only pending tasks
GET /tasks?priority=high            → Returns only high priority tasks
GET /tasks?status=pending&priority=high  → Returns pending tasks with high priority
```
