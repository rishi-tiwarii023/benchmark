# Changes Summary

## Added Priority Support to Tasks

### Files Modified

#### 1. app/models/task.py
Added `priority` field to Task model with default value "medium".

```python
priority: Mapped[str] = mapped_column(String(50), default="medium", nullable=False)
```

**Field Details:**
- **Type:** String (max 50 characters)
- **Default:** "medium"
- **Nullable:** False
- **Allowed Values:** low, medium, high

#### 2. app/schemas/task.py
Updated all three Pydantic schemas to include priority field with validation.

**TaskCreate:**
```python
priority: str = Field("medium", pattern="^(low|medium|high)$")
```

**TaskUpdate:**
```python
priority: str | None = Field(None, pattern="^(low|medium|high)$")
```

**TaskRead:**
```python
priority: str
```

#### 3. app/services/task.py
Updated `create_task()` function to pass priority when creating Task instances.

```python
def create_task(db: Session, data: TaskCreate) -> Task:
    task = Task(title=data.title, description=data.description, status=data.status, priority=data.priority)
    db.add(task)
    db.commit()
    db.refresh(task)
    return task
```

#### 4. tests/test_tasks_api.py
Added 4 new tests for priority functionality:

**test_default_priority()**
- Verifies that tasks created without specifying priority default to "medium"

**test_create_task_with_priority()**
- Verifies creating a task with custom priority (high)
- Verifies retrieving the task returns the correct priority

**test_update_task_priority()**
- Verifies updating a task's priority from low to high

**test_invalid_priority()**
- Verifies that invalid priority values are rejected with 422 status code

### Test Results
- All 11 tests pass (7 existing + 4 new priority tests)
- No existing functionality was broken
- Priority field works correctly for:
  - Creating tasks (with default or custom value)
  - Retrieving tasks (priority included in response)
  - Updating tasks (partial updates supported)
  - Validation (only allows low, medium, high)
