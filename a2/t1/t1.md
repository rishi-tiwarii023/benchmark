# Repository Analysis

## 1. **Project Structure**
```
app/
├── main.py                 # FastAPI app initialization
├── database/
│   └── session.py         # SQLAlchemy setup & DB connection
├── models/
│   └── task.py            # SQLAlchemy ORM model (Task)
├── schemas/
│   └── task.py            # Pydantic request/response models
├── routes/
│   └── tasks.py           # API endpoint handlers
└── services/
    └── task.py            # Business logic for CRUD operations
tests/
└── test_*.py              # Unit & integration tests
```

## 2. **Request Flow (Database → API)**

```
HTTP Request
    ↓
routes/tasks.py (FastAPI Router)
    ↓
depends(get_db) → Injects SQLAlchemy Session
    ↓
services/task.py (Business Logic)
    ↓
models/task.py (SQLAlchemy ORM)
    ↓
database/session.py (SQLite via engine)
    ↓
tasks.db (SQLite Database)
    ↓
Response (schemas/task.py) → HTTP Response
```

## 3. **Module Responsibilities**

| Module | Responsibility |
|--------|---|
| **main.py** | FastAPI app initialization, database table creation on startup |
| **session.py** | SQLite connection setup, session factory, dependency injection |
| **task.py (models)** | SQLAlchemy ORM definition for Task table (id, title, description, status, created_at) |
| **task.py (schemas)** | Pydantic models for request validation (TaskCreate, TaskUpdate) and API responses (TaskRead) |
| **tasks.py (routes)** | HTTP endpoint handlers; validates input, calls service layer, returns responses |
| **task.py (services)** | Pure business logic for CRUD; queries database via SQLAlchemy ORM |

## 4. **CRUD Operations**

| Operation | Flow |
|---|---|
| **Create** | `POST /tasks` → route validates TaskCreate → `task_service.create_task()` → new Task object inserted → db.commit() |
| **Read** | `GET /tasks/{id}` → route calls `task_service.get_task()` → ORM query filters by id → returns Task or None |
| **List** | `GET /tasks` → route calls `task_service.list_tasks()` → ORM query returns all tasks ordered by id |
| **Update** | `PATCH /tasks/{id}` → route validates TaskUpdate → `task_service.update_task()` → applies partial updates via setattr → db.commit() |
| **Delete** | `DELETE /tasks/{id}` → route calls `task_service.delete_task()` → ORM deletes task → db.commit() → returns success boolean |

**Key Pattern:** Routes handle HTTP concerns (validation, status codes, error responses); services handle pure business logic; dependency injection provides the DB session automatically.
