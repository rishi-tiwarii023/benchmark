## Issues Found and Fixed

### 1. Schema/Model Length Mismatch
**Severity:** Medium | **Status:** ✅ Fixed

**Problem:**
- Database model defined `title` as `String(255)`
- Schema validation enforced `max_length=100`
- Inconsistency could bypass validation at database layer

**Solution:**
- Changed model: `String(255)` → `String(100)`
- File: `app/models/task.py:13`
- Ensures consistent constraints across all layers

### 2. Whitespace-Only String Validation
**Severity:** Medium | **Status:** ✅ Fixed

**Problem:**
- Validators only checked length, not content
- Title of `"   "` (3 spaces) passed `min_length=1` validation
- Resulted in invalid tasks with only whitespace

**Solution:**
- Added `@field_validator` to both TaskCreate and TaskUpdate
- Validates strings aren't purely whitespace
- Distinguishes between `""` (valid empty) and `"   "` (invalid whitespace)
- Files modified: `app/schemas/task.py`

**Validation Logic:**
```python
@field_validator("title")
@classmethod
def title_not_whitespace(cls, v):
    if v and not v.strip():
        raise ValueError("title cannot be only whitespace")
    return v
```

### 3. Unvalidated Filter Parameters (Silent Failures)
**Severity:** High | **Status:** ✅ Fixed

**Problem:**
- GET `/tasks?status=invalid_status` silently returned empty list
- User couldn't distinguish between "no matches" and "invalid filter"
- No error feedback for typos or invalid values
- Example: `?status=pending_typo` would silently fail

**Solution:**
- Added filter validation in `list_tasks()` route
- Returns HTTP 400 (Bad Request) for invalid filters
- Provides helpful error message listing valid values
- File: `app/routes/tasks.py`

**Implementation:**
```python
if status is not None and status not in VALID_STATUSES:
    raise HTTPException(
        status_code=http_status.HTTP_400_BAD_REQUEST,
        detail=f"Invalid status. Must be one of: {', '.join(sorted(VALID_STATUSES))}",
    )
```

---

### 4. Overly Permissive Repository Update
**Severity:** Low | **Status:** ✅ Fixed

**Problem:**
- Repository `update()` used unrestricted `setattr()`
- Could theoretically update `id`, `created_at`, or other system fields
- Security: Relied only on schema validation at route layer

**Solution:**
- Whitelist allowed fields in repository
- Only permit: title, description, status, priority
- Prevents accidental or malicious field modifications
- File: `app/repository/task.py:40-46`

**Protected Fields:**
```python
allowed_fields = {"title", "description", "status", "priority"}
for key, value in updates.items():
    if key in allowed_fields:
        setattr(task, key, value)
```

---

### 5. Variable Shadowing in Routes
**Severity:** Low | **Status:** ✅ Fixed

**Problem:**
- Parameter `status` shadowed `status` module from fastapi
- Caused `AttributeError: 'NoneType' object has no attribute 'HTTP_400_BAD_REQUEST'`
- Routes couldn't access status codes during filter validation

**Solution:**
- Import as: `from fastapi import status as http_status`
- Updated all status code references to `http_status.HTTP_*`
- File: `app/routes/tasks.py:2`
