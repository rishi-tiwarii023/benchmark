# Changes Summary — GET /tasks/stats

## What changed

### `app/schemas/task.py`
- **`TaskStats`** response model:
  - `total`, `pending`, `completed`, `high_priority` (all `int`).

`completed` counts rows with `status == "done"` (API field name differs from stored status value).

### `app/repositories/task.py`
- **`count_stats(db)`** — database-backed aggregates via `func.count`:
  - **total** — all tasks
  - **pending** — `status == "pending"`
  - **completed** — `status == "done"`
  - **high_priority** — `priority == "high"`

### `app/services/task.py`
- **`get_task_stats(db)`** — calls `count_stats` and returns `TaskStats`.

### `app/routes/tasks.py`
- **`GET /tasks/stats`** → `TaskStats`, delegates to `task_service.get_task_stats`.
- Route registered **before** `GET /tasks/{task_id}` so `"stats"` is not parsed as an integer id.

## Behavior

| Request | Result |
|---------|--------|
| `GET /tasks/stats` (empty DB) | `{"total": 0, "pending": 0, "completed": 0, "high_priority": 0}` |
| `GET /tasks/stats` (with data) | Counts reflect current rows in the database |

Statistics are not derived from list pagination or in-memory filters; each metric is a separate count query.

## Tests (`tests/test_task_stats_api.py`)

- **`test_task_stats_empty_database`** — all zeros on an empty test database.
- **`test_task_stats_counts_from_database`** — mixed pending/done and high-priority tasks assert expected totals.
