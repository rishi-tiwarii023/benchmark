# Changes Summary — GET /tasks Filtering

## What changed

### `app/routes/tasks.py`
- `GET /tasks` accepts optional query parameters:
  - `status` (optional `str`)
  - `priority` (optional `TaskPriority`: `low` | `medium` | `high`)
- Both are forwarded to the service; invalid `priority` values return **422** (Pydantic validation).

### `app/services/task.py`
- `list_tasks` signature extended with optional keyword-only `status` and `priority`.
- When a parameter is omitted (`None`), no filter is applied for that field.
- Filters combine with SQL `AND` (e.g. both must match).
- Results still ordered by `Task.id` (unchanged).

## Behavior

| Request | Result |
|---------|--------|
| `GET /tasks` | All tasks (same as before) |
| `GET /tasks?status=pending` | Tasks where `status == "pending"` |
| `GET /tasks?priority=high` | Tasks where `priority == "high"` |
| `GET /tasks?status=pending&priority=high` | Tasks matching both |
