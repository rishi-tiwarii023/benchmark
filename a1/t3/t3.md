# Changes Summary — Task Priority

## What changed

### `app/models/task.py`
- Added `priority` column (`String(50)`, not null, default `"medium"`).

### `app/schemas/task.py`
- Introduced `TaskPriority` type: `Literal["low", "medium", "high"]`.
- **TaskCreate**: `priority` field, default `"medium"`.
- **TaskUpdate**: optional `priority`.
- **TaskRead**: includes `priority` in API responses.

### `app/services/task.py`
- `create_task` sets `priority` from `TaskCreate` when inserting a row.
- Updates unchanged in structure: `update_task` applies `priority` when present via `model_dump(exclude_unset=True)`.

### Tests
- **`tests/test_tasks_api.py`**: default priority on create; create/get with explicit priority; PATCH priority; **422** for invalid `priority`.
- **`tests/test_task_service.py`**: asserts default `medium` on create; update sets `priority` to `high`.

## Behavior

| Action | Priority handling |
|--------|-------------------|
| POST `/tasks` | Omit → `medium`; send `low` / `medium` / `high` → stored as given |
| GET `/tasks`, GET `/tasks/{id}` | `priority` in JSON body |
| PATCH `/tasks/{id}` | Optional `priority`; invalid value → **422** |

Full suite: **11 passed** (after priority changes).

## Scope

Routes, health endpoint, and unrelated modules were not changed.

## Local dev note

SQLite file `tasks.db` created before this column was added will not auto-migrate (`create_all` only creates missing tables). Delete or recreate `tasks.db` if the app errors on missing column.
