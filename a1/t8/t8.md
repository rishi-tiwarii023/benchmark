# Changes Summary — Task Layer Refactoring

## Goal

Reduce duplication and coupling by separating **routes**, **validation/schemas**, **business logic**, and **database access**, without changing API behavior or adding dependencies.

## What changed

### New: `app/repositories/task.py`
- **`find_many`** — filtered, ordered, paginated queries (`status`, `priority`, `limit`, `offset`).
- **`find_by_id`** — load one row by primary key.
- **`add`** — insert + `commit` + `refresh`.
- **`persist`** — `commit` + `refresh` on an existing instance (updates).
- **`remove`** — delete + `commit`.

All SQLAlchemy `Session` / `Query` usage for tasks lives here.

### `app/services/task.py`
- Orchestration only: map `TaskCreate` → `Task`, apply `TaskUpdate` via `model_dump(exclude_unset=True)`, call repository functions.
- No direct `db.query` or filter/pagination SQL.
- Public function names unchanged (`list_tasks`, `get_task`, `create_task`, `update_task`, `delete_task`).

### `app/schemas/task.py`
- **`TaskListParams`** — Pydantic model for list query validation:
  - `status`, `priority` (optional, same literals as before)
  - `limit` default **20**, `ge=1`, `le=100`
  - `offset` default **0**, `ge=0`

Replaces inline `Query(...)` constraints on the list route.

### `app/routes/tasks.py`
- `GET /tasks` uses `Annotated[TaskListParams, Depends()]` and `task_service.list_tasks(db, **params.model_dump())`.
- Body/query validation still via `TaskCreate` / `TaskUpdate` / `TaskListParams`; service calls only.
- Shared **`_not_found()`** for consistent **404** `detail="Task not found"`.

### New: `app/repositories/__init__.py`
- Re-exports `task_repository` for imports consistent with `app.services`.

## Layering (after)

| Layer | Role |
|-------|------|
| **Routes** | HTTP status codes, dependency injection, response models |
| **Schemas** | Input/output and list-query validation (Pydantic) |
| **Services** | Use cases and entity construction from validated DTOs |
| **Repositories** | Persistence and queries |
| **Models** | SQLAlchemy table mapping (unchanged) |

## Behavior

Unchanged from the client’s perspective: paths, status codes, filters, pagination limits, validation rules, and response shapes (`TaskRead`, `list[TaskRead]`) are the same as before the refactor.

## Tests

No new test files. Existing suite unchanged:

```bash
pytest tests/
```

Full suite: **36 passed** (after refactor).

Service tests (`tests/test_task_service.py`) still call `task_service` directly with `TaskCreate` / `TaskUpdate`.

## Scope

- **Added:** `app/repositories/` (task persistence).
- **Refactored:** `app/routes/tasks.py`, `app/services/task.py`, `app/schemas/task.py` (additive `TaskListParams`).
- **Unchanged:** `app/models/task.py`, `app/database/session.py`, health endpoint, no new packages in `requirements`.

## Deliberately not done

- No generic base repository, unit-of-work, or DTO mappers.
- Service still accepts Pydantic schemas (thin boundary, avoids extra mapping types).
- No response envelope or total-count metadata for pagination.
