# Repository Analysis — Task Manager (FastAPI)

## 1. Project structure

```
benchmark/
├── app/
│   ├── main.py              # FastAPI app, lifespan (create tables), router mount
│   ├── database/session.py  # SQLite engine, SessionLocal, Base, get_db dependency
│   ├── models/task.py       # SQLAlchemy Task ORM model
│   ├── schemas/task.py      # Pydantic DTOs (create/update/read)
│   ├── routes/tasks.py      # HTTP handlers under /tasks
│   └── services/task.py     # Business logic + DB queries
├── tests/                   # pytest (API + service) with in-memory SQLite override
├── tasks.db                 # SQLite file (runtime)
├── requirements.txt
├── pytest.ini
└── README.md
```

Stack: **FastAPI** + **Pydantic v2** + **SQLAlchemy 2.x** + **SQLite** (`tasks.db`).

---

## 2. Request flow (API → database)

```
Client → FastAPI (app.main) → /tasks router → get_db() → task_service → SQLAlchemy Session → tasks table
```

1. **Startup**: `lifespan` runs `Base.metadata.create_all(bind=engine)` so the `tasks` table exists.
2. **Per request**: FastAPI injects a DB session via `Depends(get_db)` (open session, yield, close in `finally`).
3. **Route**: Validates body/params with Pydantic (`TaskCreate` / `TaskUpdate`), calls `app.services.task`, maps ORM results to `TaskRead` via `response_model`.
4. **Service**: Uses the injected `Session` for queries and writes; `commit()` / `refresh()` after mutations.
5. **Persistence**: `Task` maps to SQLite through the engine in `session.py`.

## 3. Major module roles

| Module | Role |
|--------|------|
| `main.py` | App entry, table creation on startup, mounts the tasks router. |
| `database/session.py` | DB URL, engine, `Base`, session factory, request-scoped `get_db`. |
| `models/task.py` | Table schema: `id`, `title`, `description`, `status` (default `pending`), `created_at`. |
| `schemas/task.py` | API contracts and validation; `TaskRead` uses `from_attributes` for ORM serialization. |
| `routes/tasks.py` | REST mapping, HTTP status codes, 404 when service returns missing/false. |
| `services/task.py` | All CRUD against `Task`; routes stay thin. |
| `tests/` | Overrides `get_db` with an in-memory SQLite session for isolated tests. |

## 4. Task CRUD

| Operation | HTTP | Service behavior |
|-----------|------|------------------|
| **Create** | `POST /tasks` | Build `Task` from `TaskCreate`, `db.add` → `commit` → `refresh`. Returns **201** + `TaskRead`. |
| **List** | `GET /tasks` | `query(Task).order_by(Task.id).all()`. |
| **Get one** | `GET /tasks/{id}` | `filter by id, first()`; route raises **404** if `None`. |
| **Update** | `PATCH /tasks/{id}` | Load by id; if missing, **404**. Apply only set fields via `TaskUpdate.model_dump(exclude_unset=True)`, `commit`, `refresh`. |
| **Delete** | `DELETE /tasks/{id}` | Load by id; if missing, **404**. `db.delete` → `commit`. Returns **204** with empty body. |

**Note:** Delete is physical (row removed), not soft-delete. Updates are partial (PATCH semantics). `created_at` is set on the model default at insert time; it is not in create/update schemas.
