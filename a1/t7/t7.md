# Changes Summary — GET /tasks Pagination

## What changed

### `app/routes/tasks.py`
- `GET /tasks` accepts optional pagination query parameters:
  - **`limit`**: default **20**, minimum **1**, maximum **100** (`Query(20, ge=1, le=100)`).
  - **`offset`**: default **0**, minimum **0** (`Query(0, ge=0)`).
- Values outside these bounds return **422 Unprocessable Entity** (FastAPI query validation).
- `status` and `priority` filters unchanged; all parameters are forwarded to the service.

### `app/services/task.py`
- `list_tasks` extended with keyword-only **`limit`** (default `20`) and **`offset`** (default `0`).
- Pipeline: apply filters → `order_by(Task.id)` → **`offset`** → **`limit`** → `all()`.
- Omitted filters still mean no constraint on that field (same as t4).

## Behavior

| Request | Result |
|---------|--------|
| `GET /tasks` | Up to **20** tasks, ordered by `id` (default pagination) |
| `GET /tasks?limit=10&offset=0` | First 10 tasks |
| `GET /tasks?limit=10&offset=10` | Next 10 tasks |
| `GET /tasks?status=pending&limit=2&offset=1` | Filtered set, then paginated |
| `GET /tasks?limit=0` or `limit=101` or `offset=-1` | **422** |

Pagination applies **after** filtering; ordering remains **`Task.id` ascending**.

## Tests (`tests/test_tasks_api.py`)

- `test_list_tasks_pagination_limit_offset` — 15 tasks, pages of 10 and 5.
- `test_list_tasks_default_pagination_limit` — 25 tasks, unparameterized list returns 20.
- `test_list_tasks_invalid_pagination_422` — `limit` 0 / 101 / -1 and `offset` -1.
- `test_list_tasks_pagination_with_status_filter` — `status` + `limit` + `offset` together.

Existing filter and CRUD list tests still pass (default limit affects large unfiltered lists only).
