# Changes Summary — Task Input Validation

## What changed

### `app/schemas/task.py`
- **`TaskStatus`**: `Literal["pending", "done"]` (replacing free-form `str`).
- **Title** (`TaskCreate` / `TaskUpdate`): `max_length` **100** (was 255); `min_length=1`; `@field_validator` rejects whitespace-only titles.
- **Description**: optional, `max_length=500` on create and update.
- **Status / priority**: `TaskStatus` and `TaskPriority` on create, update, and read (`TaskRead`).

Invalid request bodies or query values are rejected by FastAPI/Pydantic with **422 Unprocessable Entity**.

### `app/models/task.py`
- `title` column: `String(100)` (aligned with API max length).

### `app/routes/tasks.py`
- `GET /tasks` filter `status` typed as `TaskStatus | None` (invalid filter values → **422**).

## Validation rules (summary)

| Field | Rules |
|-------|--------|
| `title` | Required on create; not empty / not blank; max **100** chars |
| `description` | Optional; max **500** chars |
| `status` | `pending` or `done` only |
| `priority` | `low`, `medium`, or `high` only |

## Tests (`tests/test_task_validation_api.py`)

- **Valid**: varied creates including 100-char title and 500-char description; successful PATCH.
- **Invalid create**: empty/blank title, overlong title/description, bad status/priority, missing title.
- **Invalid update**: same classes of errors on PATCH.
- **Invalid list filter**: `GET /tasks?status=bogus` → **422**.

Existing task API tests remain valid under the stricter schemas.
